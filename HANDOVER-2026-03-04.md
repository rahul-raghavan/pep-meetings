# Handover — 2026-03-04

## Session Summary
This session focused on making the PEP Meetings transcription pipeline work reliably for long meetings (1hr+), improving the quality of AI-generated summaries and action items, and adding several quality-of-life features like regenerating analysis, replacing speaker labels with real names, and a global find-and-replace tool.

## What Was Done

- **Audio chunking for long meetings** — Created `src/lib/split-audio.ts` that splits audio files longer than 45 minutes into chunks using ffmpeg, then transcribes each chunk separately. Updated `src/app/api/meetings/[id]/transcribe/route.ts` to loop through chunks, offset timestamps so they're continuous, and offset speaker IDs so they don't collide between chunks.
- **Fixed ffprobe dependency issue** — Initially used `ffprobe-static` for duration detection, but it failed on deployment (platform-specific binary not available). Replaced with ffmpeg-based duration detection (parsing `Duration: HH:MM:SS` from stderr), so we only depend on `ffmpeg-static` which was already working.
- **Speaker names in summaries** — Added `replaceSpeakerLabels()` function to the meeting detail page that swaps `SPEAKER_01` etc. with display names everywhere summaries are shown (overview, topic sections, key decisions, downloads). This is display-time substitution, so it updates automatically when you rename a speaker.
- **Upgraded analysis model** — Switched from `gpt-4o-mini` to `gpt-4o` for meeting analysis. Rewrote the prompt to produce richer, more specific summaries and extract more action items.
- **Extracted shared analysis logic** — Created `src/lib/analyze-meeting.ts` with the GPT analysis function, used by both the transcribe route and the new regenerate route.
- **Regenerate Analysis feature** — New API route `/api/meetings/[id]/regenerate` that re-runs the GPT analysis on existing transcript segments without re-transcribing. "Regenerate Analysis" button added to the Summary tab.
- **Dropped assignment from action items** — Removed the "Assigned to" field from action items (prompt, DB insert, display, add form, email export, download). Action items are now simple descriptions.
- **Find & Replace feature** — New API route `/api/meetings/[id]/find-replace` and UI button on the meeting page. Does a global find-and-replace across transcript segments, summary text, topic sections, key decisions, and action items. Shows a count of what was updated.

## Current State

Everything is **working and builds cleanly**. The user can:
- Upload short meetings (works as before, no splitting)
- Upload long meetings (1hr+) — auto-splits into 45-min chunks
- Label speakers and see real names in summaries
- Regenerate the AI analysis on any existing meeting
- Use Find & Replace to fix spelling across the entire meeting
- Action items show as simple checklist without assignments

## Open Issues / Next Steps

- **Speaker merging across chunks** — When a long meeting is split into chunks, the same person gets different speaker IDs in each chunk (e.g., SPEAKER_01 in chunk 1 and SPEAKER_03 in chunk 2). Users need to manually merge these using the existing merge-speakers feature. A future improvement could try to auto-detect same speakers across chunks.
- **Re-transcribe needed for old meetings** — Existing meetings still have the old `gpt-4o-mini` analysis. Users need to click "Regenerate Analysis" to get the improved summaries. New transcriptions will use `gpt-4o` automatically.
- **gpt-4o cost** — The model upgrade is ~10x more expensive per call than `gpt-4o-mini`. Worth it for quality, but something to monitor if usage grows.

## Key Decisions Made

- **45-minute chunk size** — Chosen to stay well under Mistral's capacity limits. Could be tuned if needed.
- **ffmpeg for duration detection** (not ffprobe) — `ffprobe-static` failed on deployment because it bundles platform-specific binaries. ffmpeg was already proven to work, so we parse duration from its stderr output.
- **Display-time speaker name substitution** — Instead of re-running GPT when speakers are labeled, we replace `SPEAKER_XX` with real names at render time. Simpler and updates automatically.
- **gpt-4o over gpt-4o-mini** — User felt summaries and action items from mini were too thin. The quality difference is significant.
- **More action items > fewer** — Prompt explicitly tells GPT to cast a wide net. Users can delete irrelevant ones, but missing important ones is worse.
- **No assignments on action items** — Simplified to just descriptions. The assigned_to field is still in the DB schema but we pass null.

## Important Context

- **Node 20 required** — Always use `nvm use 20` before building or running.
- **ffmpeg-static** is the only binary dependency — no ffprobe. Duration detection uses `ffmpeg -i file -f null -` and parses the `Duration:` line from stderr.
- **`src/lib/analyze-meeting.ts`** is the single source of truth for the GPT prompt and analysis logic. Both `/transcribe` and `/regenerate` routes import from it.
- **Find & Replace is case-sensitive** — it does exact string matching, not regex.
- The `assigned_to` column still exists in `pep_action_items` table — we just always set it to null now. No migration needed.
