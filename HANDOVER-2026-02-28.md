# Handover — PEP Meetings App

**Date:** 2026-02-28

## Session Summary

We built the entire PEP Meetings app from scratch — a tool for PEP School to record, transcribe, and extract action items from meetings (parent-teacher, admission, training). Teachers upload audio files, the app sends them to Voxtral for transcription with speaker identification, then GPT-4o-mini pulls out action items and a summary. Teachers can then label who each speaker is ("Speaker 1" → "Mrs. Sharma") and manage action items.

## To Get It Running

1. **Run all migrations in order** — open your Supabase project's SQL Editor and run each file one at a time, in this order:
   1. `supabase/migration.sql` — base schema (tables, RLS, storage bucket)
   2. `supabase/migration-002-sentiment.sql` — sentiment analysis fields
   3. `supabase/migration-003-rbac.sql` — RBAC roles, campuses, classes
   4. `supabase/migration-004-locations.sql` — location/campus updates
   5. `supabase/migration-005-invite-users.sql` — user invitation flow
   6. `supabase/migration-006-multi-class-meetings.sql` — meetings linked to multiple classes
   7. `supabase/migration-007-meeting-types.sql` — meeting type categories
   8. `supabase/migration-008-action-item-source.sql` — ai/manual source tracking for action items
2. **Set env vars** — copy `env.local.example` to `.env.local` and fill in:
   - `NEXT_PUBLIC_SUPABASE_URL` — your Supabase project URL (include `https://`)
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` — from Supabase dashboard → Settings → API
   - `SUPABASE_SERVICE_ROLE_KEY` — same place, the service role key
   - `MISTRAL_API_KEY` — from console.mistral.ai
   - `OPENAI_API_KEY` — from platform.openai.com
3. **Set up Google OAuth** — run `/google-oauth-setup` for the step-by-step guide, or manually configure Google Cloud Console + Supabase Auth
4. **Use Node 20** — run `nvm use 20` before starting
5. **Install dependencies** — `npm install`
6. **Start dev server** — `npm run dev`

## Key Decisions Made

- **Voxtral Mini Transcribe V2** over OpenAI Whisper (cheaper at $0.003/min, supports 3hr audio and unlimited speakers vs Whisper's 25min/4 speaker limits)
- **GPT-4o-mini** for action item extraction (cheapest model that handles structured JSON extraction well)
- **All users see all meetings** — no per-user data isolation since it's a school-wide tool
- **Auto-create user on first login** — any Google account that authenticates gets a `pep_meeting_users` row automatically as "staff"
- **Sequential pipeline** (upload → transcribe → extract) runs in one request rather than background jobs, with a 5-minute timeout via `maxDuration = 300`
- **Speaker labels normalized** — Voxtral returns "Speaker 1", we store as "SPEAKER_01" for consistency

## Important Context

- **Node 20 required** — Next.js 16 and Tailwind v4 need Node 20+. The machine has Node 18 as default, so always `nvm use 20`
- **`proxyClientMaxBodySize: '100mb'`** is set in `next.config.ts` for large audio uploads
- **Voxtral response format** — returns `{ segments: [{ speaker_id: "Speaker 1", start, end, text }] }` when diarization is enabled
- **LLM JSON parsing** — the code strips markdown fences before `JSON.parse()` since models often wrap JSON in ````json` blocks
- **Service role client** used for the transcription pipeline (needs to write segments/action items regardless of RLS)
- **`env.local.example`** is named without the dot prefix because `.env*` is in `.gitignore`
